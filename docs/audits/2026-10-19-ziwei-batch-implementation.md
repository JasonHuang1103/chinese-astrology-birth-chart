# 紫微排盘规则修复与分层批量输出验收

日期：2026-10-19。本文接续[首次功能核查](2026-10-19-ziwei-capability-audit.md)。规则与独立对照测试使用合成生辰；个人文件迁移按后续用户授权另行执行。

## 已实现的行为

| 要求 | 本轮交付 |
| --- | --- |
| 闰月晚子时一致性 | 按已选 `forward` 约定，先整体推进到次日早子，再统一换算农历年月日并安星；保留原始和真太阳民用记录 |
| 全部大限 | 按十二段本命大限表逐段输出，包含121–125岁中适用的末限尾段，不再被无关的小限表拦截 |
| 全部流年与流月 | 从实际出生时刻至末限结束，逐农历年、实际月份导出；闰月单独一文件，十五／十六分界分别保存状态 |
| AI可追溯JSON | 共享完整本命，层文档含 `chart_id`、`layer_id`、父层相对引用、自然／有效区间及层级宫位、四化、动态星与关系 |
| 输出可核查 | 清单列全部文档、层级、区间、月身份及精确文件字节SHA-256 |
| 写盘保护 | 新目录导出、私有暂存、校验后发布、已有路径不覆盖、manifest最后发布 |
| 独立对照 | 固定HKO历表与古典安星规则手推的本命样本、晚子边界对照、运限手推；明确保留流派异文和转录歧义 |

## 晚子规则的核实与修复

采用现有默认 `dayDivide=forward`、`fixLeap=true`，但修复旧引擎只推进日数、没有统一推进月年及闰月月序的问题。整日推进是本项目明确选择的统一语义，不能推广为各流派唯一标准。

主案例2023-04-07晚子与2023-04-08早子，均使用癸卯年闰二月十八、安宫月序三，命身丙辰、土五局、紫微未。预期来自香港天文台日期、命身与纳音／起紫微规则的手算，并用另一独立实现的相容步骤交叉参考；没有用当前程序的输出生成预期。

七对固定边界覆盖闰月十五、十五至十六、后半月、闰月末、普通月末及两个春节。全部先观察旧代码失败，再修复通过。依据与兼容性变化见[晚子规则文档](../references/ziwei-late-zi-convention.md)。

`chart.solar_date`、`chart.lunar_date_details` 记录真太阳民用日期；`chart.calculation_lunar_date_details` 记录实际计算用农历及有效安宫月序。原始23时输入和索引12仍保留，显示仍为晚子时。旧的受影响输出需要重新生成。

## 批量输出契约

入口：

```sh
node bin/ziwei-json.js \
  --date 2000-08-16 --time 14:30 --gender female \
  --latitude 0 --longitude 120 --time-zone Asia/Taipei \
  --ziwei-output batch --name example
```

默认输出到 `output/example/`，自动创建 `output/`。个人目录下按 `本命/紫微.json`、`大限/`、`流年/`、`流月/` 分类，`manifest.json` 放在个人目录根部；姓名记录在各层但不参与 `chart_id`。显式 `--output-dir` 仍表示准确目标目录，其父目录须已存在。目标目录必须不存在，已有导出不覆盖。该合成输入实际产生：

| 层级 | 文件数 |
| --- | ---: |
| 本命 | 1 |
| 大限 | 12 |
| 流年 | 125 |
| 实际农历月 | 1,540 |
| 清单 | 1 |
| 合计 | 1,679 |

46个闰月分别保存两段，合计1,586个流月状态段。最后一限为116–125虚岁，有效区间从2115-01-26零时至2125-02-03零时（Asia/Taipei）。不同生辰的局数、大限年龄、首年裁切与闰月数量会改变文件数。

- 每层通过 `natal_ref` 读取共享本命的全部星曜、庙旺、生年四化、宫干飞化、自化、借宫和索引。月文件另有 `year_ref` 和适用的 `decadal_ref`，不把重复本命拷贝成不同盘。
- 每层保留本层十二宫名映射、四化落点、动态星、叠宫、三方四正与借宫引用。文件只包含请求层，不混入无关流日／流时。
- `period.natural` 保存自然周期，`period.valid` 保存出生和生命周期范围裁切后的区间。端点保留当地日期、时分、时区、偏移及UTC时刻，以UTC半开区间比较。
- 缺失午夜顺延到首个有效分钟；重复午夜取第一次。Apia整日跳过、Sao Paulo月首午夜跳跃和Havana月首午夜重复均有测试。
- 年界、运限界与虚岁仅支持 `normal`；其他配置明确拒绝。出生真太阳校正跨春节可能产生初始虚岁0或首年虚岁2，仍保留真实年／月区间，并注明无大限引用原因。
- 起限前的年／月文件没有独立大限引用，不额外制造童限文件。原有六层快照仍按其小限表范围拒绝121岁以上；批量模式的有效层不受此限制。

计算是流式生成器，只保留清单元数据。出生参数在第一次生成时复制；中途修改全局计算配置会明确报错。每次运限计算固定输出语言，避免调用方切换语言后产生无法解析的四化引用。

写盘先在同父目录的私有暂存目录完成生成与哈希／引用检查，再独占创建目标目录，逐文件以不覆盖的hard-link发布，最后写入manifest。要求目标文件系统支持hard-link。发布阶段的中断可能留下无manifest的新目录；该目录不是完成的导出。失败只清理本次暂存，已有或竞态出现的目录／文件不会被删除或替换。

### 明确的表异文与转录歧义

保持当前默认表，没有为了匹配古籍而拼接流派：

| 项目 | 当前采用 | 所引用转录中的值／问题 |
| --- | --- | --- |
| 壬年化科 | 左辅 | 天府 |
| 辛年魁钺 | 天魁午、天钺寅 | 天魁寅、天钺午 |
| 丙丁天钺 | 酉，另有独立Fortel表支持 | 转录写“猪狗”，对应戌；未据影印底本校勘，不能自行改成“猪鸡”再称古籍吻合 |

三项写入 `calculation_conventions.table_variants`。前两项按具名表异文验证，第三项明确限定转录来源。古籍转录版见[固定修订卷二](https://zh.wikisource.org/w/index.php?title=紫微斗數全書/卷二&oldid=1963110)，独立表见[Fortel固定提交](https://raw.githubusercontent.com/airicyu/fortel-ziweidoushu/2620cc895395f9f6994abd4927e739d31015c67d/src/model/minorStar.ts)，日期见[香港天文台](https://www.hko.gov.hk/tc/gts/time/conversion1_text.htm)。

## 按姓名重建现有命盘

后续按用户明确授权，使用根目录原JSON中的出生参数，为5人重新生成完整紫微批量文件，另重新生成原有1份八字盘。原JSON没有中文姓名，目录沿用原文件的姓名标识。输出共8,262个JSON：8,261个紫微文件（含5份清单）及1份独立八字文件。

逐文件核对JSON解析、清单字节哈希、姓名与命盘身份、相对引用、十二大限及年／月连续覆盖，并确认新本命／八字的输入与原文件完全一致。所有替代文件验证成功且原文件哈希未变后，才删除根目录6份旧命盘。八字存放在对应姓名的 `本命/八字.json`，不计入紫微清单；个人输出目录由Git忽略。

```sh

```

现有默认体系的星曜与关系均保留；部分辅杂曜亮度仍为 `null`，明确表示引擎未提供，不能补造或当作所有流派不适用。独立测试没有穷举火铃、全部杂曜和亮度、所有动态辅杂星、所有出生日期或所有流派。
