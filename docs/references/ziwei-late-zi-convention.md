# 晚子时与闰月分界：本项目采用的计算约定

核查日期：2026-10-19。仅使用下列合成生辰；没有读取个人命盘。

## 采用语义与来源边界

本项目保留既有 `dayDivide=forward`、`fixLeap=true`，将它们一致解释为：先按实际采用的真太阳时判断晚子时；晚子时的**计算日期整体进到次日**，按次日早子时排盘；再从这个有效日期取得农历年月日，闰月初一至十五采用本月月序，十六日起采用下一月月序。月序调整用于安宫与月系星，不把农历日期改写成普通三月，也不把十八日减十五成为初三。

[iztro 官方配置说明](https://www.iztro.com/posts/config-n-plugin#配置)将 `forward` 定义为晚子时归次日，`current` 为归当日。这能说明所选开关的语义，不能独立证明安星位置。该在线文档已含 2.6.2 行为，本次问题发生于安装版 2.5.8；没有以新版本实现替代本地代码核查。

独立实现 `RedSC1/ziwei_core`，固定提交 `f7700c91ba683df2b0da9386d842171a6aec835f`：其 [`calendar.dart` 第153–157行](https://github.com/RedSC1/ziwei_core/blob/f7700c91ba683df2b0da9386d842171a6aec835f/lib/src/calendar.dart#L153-L157)先将 `nextDay` 下23时之后移至翌日；[第203–244行](https://github.com/RedSC1/ziwei_core/blob/f7700c91ba683df2b0da9386d842171a6aec835f/lib/src/calendar.dart#L203-L244)再整体换算农历，以所得日期判断闰月十五／十六，最后把同一有效年月日交给安宫安星。这是另一实现中相容的计算次序；本次阅读了源码，没有运行其 Dart 引擎，不把它称为外部金标准命盘。

另一独立实现 `airicyu/fortel-ziweidoushu`，固定提交 `2620cc895395f9f6994abd4927e739d31015c67d`：[`DestinyConfig.getLogicalMonth()`](https://github.com/airicyu/fortel-ziweidoushu/blob/2620cc895395f9f6994abd4927e739d31015c67d/src/model/destinyConfig.ts)明确在闰月 `day > 15` 时将月序加一；[`DestinyBoard` 的安命身与五行局](https://github.com/airicyu/fortel-ziweidoushu/blob/2620cc895395f9f6994abd4927e739d31015c67d/src/model/destinyBoard.ts)以及 [`MajorStar` 的逐日紫微表](https://github.com/airicyu/fortel-ziweidoushu/blob/2620cc895395f9f6994abd4927e739d31015c67d/src/model/majorStar.ts)可独立复核以下安宫、五局和主星预期。此处只采用这些相容规则，没有把该库其他流派选项带入项目。

这并非所有流派唯一规则。星侨软件官方[《神算紫微》使用手册第26页](https://www.nccsoft.com/soft/download/T00/manual/Book-T07_new.pdf#page=26)分别列有晚子归日及闰月本月／十五分界／下月等选项，证明这些需要明确选择。《紫微斗数全书》卷二“安身命例”的[维基文库固定转录版 oldid=1963110](https://zh.wikisource.org/w/index.php?oldid=1963110&title=紫微斗數全書/卷二#安身命例)采用闰月整月作次月的安命身方法，**不是本项目十五分界法的古籍依据**。该转录页未标明影印底本，本文仅用其可逐字核对的安宫、五虎遁、纳音和安星表交叉参考，不主张已完成古籍版本校勘，也不以它裁定晚子归日之争。

## 主案例的手工推算

合成输入：男性、纬度0、经度120、`Asia/Taipei`。2023-04-07 23:30 与 2023-04-08 00:30 校正后仍分别落在晚子、早子。

1. [香港天文台2023年公农历对照表](https://www.hko.gov.hk/tc/gts/time/calendar/pdf/files/2023.pdf)给出4月7日为癸卯年闰二月十七、4月8日为闰二月十八。`forward` 下，两者的计算日期都是4月8日，即闰二月十八。
2. 十八大于十五，`fixLeap=true` 采用三月月序。寅起正月顺至三月为辰；子时不再移动，命宫与身宫均在辰。
3. 癸年按五虎遁从甲寅起，顺至辰为丙辰；丙辰纳音沙中土，所以是土五局。
4. 土五局十八日，补二成为二十，除五得四；寅起第一宫顺数四宫到巳，补数为偶数再顺二宫至未，所以紫微在未。这也与独立实现的土五局逐日表第十八项、经典土五局表相符。

## 固定回归预期

每行左日期取23:30，右日期取00:30；均用上述相同的合成地点与默认规则。年份、农历月日和闰月标志来自香港天文台[2023年表](https://www.hko.gov.hk/tc/gts/time/calendar/pdf/files/2023.pdf)及[2022年表](https://www.hko.gov.hk/tc/gts/time/calendar/pdf/files/2022.pdf)，命身、宫干支、五局、紫微由前述规则独立推算。测试中使用这些字面预期，不调用 iztro 的辅助函数生成期望值。

十五日：水二局，补一除二得八，寅起八宫到酉，奇数补一逆退至申。十六日：土五局，补四除五得四，巳顺四至酉。初一日：土五补四，寅顺四至午；水二补一，寅逆一至丑；金四补三，寅逆三至亥。宫干支均按该有效农历年的年干起五虎遁。

## 对旧输出的影响与验证限度

iztro 2.5.8 的 `fixLunarMonthIndex` 用原始日期判断闰月后半月，且排除 `timeIndex === 12`；紫微日数则另行加一天。月末时仅把日数回到初一，不统一更新安宫月份。于是晚子时可以混用原月／原年与次日日数。只删除排除晚子的条件，仍无法解决十五日晚子进入十六日、普通月末以及春节前一日晚子的问题。

最小适配是在进入排盘引擎前统一选择一次有效日期和时辰：仅 `forward` 晚子用次日日期和早子索引0，其他情况保留既有输入。实际出生输入、真太阳时日期、晚子索引12及显示标签分别保留；有效日期和计算农历另行记录。春节案例会由有效农历年重新安年干、宫干、年系星和四化，这是所选整体换日约定的兼容性变化，不能描述成旧引擎已经如此实现。

本组预期验证选定边界及主星起位，不证明全部辅杂曜、庙旺表、真太阳时精度或所有运限规则均已完成独立验证；也不把两相邻时刻的记录日期、实际生日或年龄起点强行改成同一时刻。
